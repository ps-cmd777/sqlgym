# sqlgym

> Interview-grade SQL training in the browser. An original 12-module curriculum from `SELECT` to the interview gauntlet, graded by **executing your query against real Postgres** (PGlite/WASM) and comparing results — including a hidden dataset your query has never seen. No backend, no account; nothing leaves your machine.

## Why this exists

The good SQL-prep resources split into two camps: problem banks with graders but no teaching (DataLemur, StrataScratch style) and interactive textbooks with teaching but no interview-level difficulty (SQLBolt, Select Star SQL style). sqlgym is both: theory → worked patterns → execution-graded exercises that ramp to genuine mid-senior interview difficulty, plus a timed interview mode that mimics a live screen.

Everything is original: the curriculum, all 70 problems, the three practice datasets, and every canonical solution. Nothing is copied from any platform.

## The grader

String-matching graders are toys. sqlgym runs your SQL and the canonical solution against the same database and compares **results**:

- **Multiset comparison** — row order doesn't matter (unless the problem demands ORDER BY), but duplicates do: an accidental join fan-out or missing DISTINCT fails, exactly as it should.
- **Normalization** — `NUMERIC` strings vs numbers, dates vs timestamps, float noise: all compared sanely. Column aliases are yours to choose; column *count* is enforced.
- **Diff feedback** — not "wrong," but "2 expected rows missing, 1 unexpected — here are samples."
- **A hidden dataset** — every problem re-grades your query against a second, differently-seeded database. Hard-coding the visible answer passes visibly and fails hidden, and the message tells you why.

## The curriculum

| # | Module | The interview patterns it drills |
|---|---|---|
| 1 | Foundations & NULL traps | COUNT(*) vs COUNT(col), `!= NULL`, HAVING vs WHERE |
| 2 | Joins & fan-out | anti-joins, LEFT JOIN + ON conditions, row multiplication |
| 3 | Subqueries, EXISTS & set ops | correlated subqueries, the NOT IN NULL bug, INTERSECT/EXCEPT |
| 4 | Expressions: strings, dates & CASE | function fluency, TO_CHAR, NULLIF division safety, STRING_AGG |
| 5 | CTEs & composition | multi-step aggregates, narratable query structure |
| 6 | Window functions I | ROW_NUMBER/RANK/DENSE_RANK, top-N per group, latest record |
| 7 | Window functions II | LAG/LEAD, running totals, moving averages, % of total, MoM growth |
| 8 | Classic patterns | dedup, **gaps-and-islands streaks**, FILTER pivots, date spines |
| 9 | Hierarchies & recursive CTEs | org charts, WITH RECURSIVE, subtree aggregates, path strings |
| 10 | Writing data & transactions | INSERT/UPDATE/DELETE, UPSERT, atomic multi-statement — graded by resulting **state** on a fresh DB copy |
| 11 | Product analytics | retention, funnels, cohorts, MRR, segmentation |
| 12 | Interview gauntlet | mixed hard set + how to run a live screen |

**Timed interview mode**: 5 problems, 40 minutes, no hints — a deterministic daily draw from the interview-eligible pool, with an end-of-run readout.

## Run it

```bash
npm install
npm run dev        # http://localhost:8040
```

```bash
npm run validate   # executes all 70 canonical solutions on BOTH dataset variants
npm test           # grader unit tests (normalization, multiset, ordering, NULLs)
npm run build      # typecheck + production build
```

## Architecture

- **React + TypeScript + Vite**, CodeMirror 6 editor with Postgres syntax.
- **PGlite** — real Postgres compiled to WASM (~3 MB), one in-memory instance per (schema, variant), lazily created. Real `FILTER`, `PERCENTILE_CONT`, `generate_series`, window frames — because interviews are Postgres-flavored.
- **Content as typed code** — problems are TypeScript objects; `npm run validate` executes every canonical solution against both dataset seeds in CI, so a broken problem cannot ship.
- **Seeded original datasets** — a music-streaming schema (streaks, retention, MRR), a marketplace schema (fan-out, revenue, refunds), and an org-chart schema (recursion, self-joins), generated by a deterministic PRNG in [src/data/datasets.ts](src/data/datasets.ts).
- **Progress in localStorage; drafts in sessionStorage.** No server, no telemetry.

Phase 2 (planned): Python/pandas track via Pyodide, reusing the same "run → produce table → compare" grading contract.
